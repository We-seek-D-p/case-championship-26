# Единая фактическая база: TASK-01

Сборка из корня репозитория: `uv run python scripts/build_core.py`.
Используется только стандартная библиотека Python; сеть, `data/raw/` и парсеры
первичных публикаций не нужны. Входные файлы не изменяются. Сборка перезаписывает
только четыре CSV этого каталога, печатает учёт входных строк и выполняет проверки.
Отчёт о покрытии: [05-baseline.md](../../../analysis/05-baseline.md).

Сам `uv run` может синхронизировать окружение и обновить существующий `uv.lock`
независимо от скрипта. Если Python 3.14 уже доступен, полностью автономный запуск
без такой синхронизации: `python scripts/build_core.py`; для готового uv-окружения —
`uv run --frozen --no-sync python scripts/build_core.py`.

| Файл | Строк без заголовка | Гранулярность |
|---|---:|---|
| airports.csv | 156 | Опубликованная количественная метрика × аэропорт × период × область × источник, включая базу сравнения |
| route_passengers.csv | 33 | Опубликованный пассажиропоток линии × аэропорт публикации × город назначения × период × источник |
| current_routes.csv | 638 | Отдельное маршрутное свидетельство или вариант расписания на период |
| market.csv | 526 | Показатель × субъект × период × область × источник × база отчётности |

## Поля и правила преобразования

Обязательные поля TASK-01 сохранены. Дополнительные поля обеспечивают точную
прослеживаемость: `source_row` — физическая строка начала записи во входном CSV
(заголовок — строка 1); `raw_path` — только имеющаяся ссылка на исходник, без
проверки его наличия; `source_url` — опубликованный URL из входа или реестра;
`source_processed_file` — промежуточный файл, когда указан во входе.
`source_file` всегда обозначает реально читаемый входной CSV.
`original_value`, `original_unit`, `comparison_period`, `reporting_basis`
сохраняют исходную точность и контекст. Текстовые выдержки страниц не копируются.

- Все 188 строк `airports/metrics.csv` используются: 33 строки `passengers`
  с `scope=route:…` перенесены в `route_passengers`, остальные 155 — в `airports`.
  Из `attributes.csv` добавлен только `maximum_takeoff_weight=191`; единица и
  период остаются пустыми. Коды, UTC, составные размеры и качественные атрибуты
  не интерпретируются как количественные метрики. `relations.csv` не создаёт рейсов.
- `route_passengers.origin` — аэропорт, опубликовавший показатель, а не доказанная
  сторона перевозки. Во всех 33 строках `traffic_type=unspecified`;
  `record_kind=observation`. Назначения сохраняют исходный уровень города.
  Это перевозки на линии, не конечный O&D и не уникальные пассажиры.
- Расписание импортируется только из `flights/scheduled_departures_winter_2026_27.csv`:
  S19 — 475, S20 — 65 строк. Отдельные `schedules/S19.csv`, `S20.csv` не читаются.
  Коды аэропортов копируются только из объединённого файла. Для `airlines/routes.csv`
  IATA остаются пустыми; даже совпадение названия города не определяет аэропорт.
- В перевозчиках только однозначное `RED WINGS` приводится к `Red Wings`;
  `original_airline` сохраняет исходное значение. Прочие названия не исправляются
  по внешним справочникам. Названия городов/аэропортов не унифицируются догадками.
- `operating_days` и `validity_period` копируются дословно. Даты без года не
  разворачиваются. `start_date`, `end_date` из авиакомпаний сохраняются отдельно.
  Время S61 записано в поля `*_local` по требуемой схеме, но часовая основа
  неизвестна, что явно оставлено в `limitations`.
- `flights_per_week` берётся из опубликованной частоты; если её нет, считается
  количество уникальных явно перечисленных дней недели (ежедневно = 7).
  `frequency_basis=planned_operating_days_full_week` означает запланированные дни
  в полной неделе; `published_planned_flights_per_week` — опубликованную частоту.
  Это не среднее число фактически выполненных рейсов. Пустые дни дают пустую частоту.
- `evidence_type=published_schedule` для строк расписаний; `announced_route`
  для `announced_service` и `plan`, включая старые анонсы. `historical_route`
  используется только для `reported_service`/`resumed_service` с явно прошедшим
  периодом или датой среза. Явные правила перечислены в `evidence()`; при отсутствии
  такого правила — `unknown_status`. Опорная дата фиксирована: 2026-11-10.
  Исторический тип не доказывает закрытие линии; анонс не доказывает её выполнение.
  `issue_2026-01` — контекст номера журнала, не установленная конечная дата графика.
- Все 130 метрик авиакомпаний сохранены в `market`, в том числе финансовые,
  технические и аэропортовые контекстные показатели. Фильтровать по `entity`,
  `metric`, `scope`, `record_kind`, `reporting_basis` перед сравнением.
  S02: `scope=segment; service_type=…`. S03: `scope=segment`.
  Для шести строк `airline_rank` исходное `unit` перенесено в `entity`, а `unit=rank`.
  Это явное исправление семантики схемы core без изменения исходного CSV.
- Единицы и масштабы S02/S03 сохраняются без пересчёта; `тыс.пасс.км.`, `млн человек`
  и базовые `person` нельзя сравнивать как одинаковые числа. `% к предыдущему году`
  в S02 — относительный индекс; `%`, `п.п.`, `percent_as_reported` не взаимозаменяемы.
  У S02/S03 без исходного квалификатора ставится `reported`: опубликованная
  точность, а не гарантия точного подсчёта. Квалификаторы остальных входов копируются.

Пустое поле означает неизвестность или неприменимость; нули не подставляются.
`record_kind` исходных записей сохранён, включая планы, прогнозы и спецификации.
Вложенные области, повторные публикации и разные годы не агрегируются.
Разные источники одного показателя остаются отдельными свидетельствами.
Для уникальности записи служит `(source_file, source_row)`, а не пара городов.

## Проверки

При запуске проверяются ширина строк CSV, уникальность provenance, наличие source_id
в реестре, сохранение исходных значений, квалификаторов, локаторов, периодов,
базы сравнения и ограничений, числовой формат, S19/S20 без повторного импорта,
типизация анонсов и рейтингов, несколько предметных примеров. Баланс входных строк
печатается как `total = used + excluded + not_applicable`; метаданные учитываются
отдельно от фактов. Повторная сборка сравнивается побайтно в памяти с записанными CSV.
Хеш-аудит и дополнительные артефакты не создаются.

`sources.csv` и реестр устанавливают происхождение локального извлечения;
это не независимая проверка сайтов издателей. Статусы реестра не обновляются.
