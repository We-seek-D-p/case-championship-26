## Происхождение обязательно учитывать

`documentation/DATA_LINEAGE.csv` связывает каждую основную числовую меру с источниками и оценкой. `observed` означает опубликованное значение, в том числе округлённое и унаследованное из исходного исследования; это не обещание независимой повторной проверки. `derived` — арифметика/нормализация; `estimated` — модель или аналог; `scenario` — условное допущение. Сценарные нули NUX не являются опубликованным нулём МВЛ. Пустая ячейка — неизвестно.

Для фактических сравнений сначала фильтруйте происхождение. Смешивать все заполненные ячейки как факты нельзя. Число записей происхождения: observed 1430, derived 216, estimated 1853, scenario 285. Это счётчики значений/свойств в lineage, а не число независимых фактов. Число записей расчётов: 2070.

## Чтение

```python
from pathlib import Path
import pandas as pd

root = Path("data/airport_research")
annual = pd.read_csv(root / "processed/airport_annual.csv")
monthly = pd.read_csv(root / "processed/airport_monthly.csv")
lineage = pd.read_csv(root / "documentation/DATA_LINEAGE.csv", keep_default_na=False)

# Происхождение годового общего потока; ключ entity_id = IATA, period = YYYY.
origin = lineage.query("entity_type == 'airport_annual' and metric == 'passengers_total'")
annual["period"] = annual["year"].astype(str)
annual = annual.merge(origin[["entity_id", "period", "value_origin", "source_ids", "estimate_id"]],
                      left_on=["airport_iata", "period"], right_on=["entity_id", "period"], validate="one_to_one")
observed_annual = annual.query("value_origin == 'observed'")
```

CSV: UTF-8 без BOM, запятая, десятичная точка. Числа пассажиров и операций — целые; тоннаж допускает дробь. Географические координаты — WGS84. Часовые пояса — IANA. Даты ISO 8601; отсутствие дня в исходной публикации не превращается в выдуманную дату.

## Ключи и важные правила

- `airports`: IATA; `annual`: IATA+year; `monthly`: IATA+year+month.
- `operations`: IATA+year+metric. ВПО, вылеты, прилёты, обслуженные ВС и неопределённые «рейсы» хранятся раздельно.
- `cargo`: IATA+year+scope. У Внуково две строки на год: опубликованная обработка с автоподвозом и отдельная оценка воздушного объёма. Их нельзя складывать.
- `infrastructure`: IATA+as_of_date+runway_id. Мощность терминала повторяется по ВПП; её нельзя суммировать по полосам.
- Маршруты: составной ключ и `route_id` находятся в `documentation/ROUTE_KEYS.csv`. Строка — наблюдение конкретной версии расписания, а не полная история маршрута. Сопоставляйте исходящие и входящие аэропорты; три аэропорта представлены только как второй конец пары.
- Наличие маршрута не делает все поля строки фактическими: частота, тип, кресла и окно ёмкости имеют собственное происхождение. Неизвестный перевозчик пустой, а не вымышленный.
- `route_capacity`: сценарная ёмкость пары в обе стороны; не число перевезённых пассажиров. Не складывать перекрывающиеся версии расписания и зеркальные направления.
- `airline_market_annual`: отдельные авиакомпании и самолётный сегмент группы ЮТэйр имеют разные scope. Знаменатель — перевозки российских авиакомпаний, не сумма обслуживания аэропортов. Перевозчики за пределами таблицы остаются частью рынка.
- Трансфер — самостоятельная характеристика внутри потока. Транзит учитывается как добавочный компонент только в явно соответствующих публикациях PEE/CEK. Необъяснённый остаток не переименовывается в транзит.
