# Правила проекта Red Wings

## Среда и код
- Python 3.14; запускать команды через `uv`.
- Для готового окружения использовать `uv run --frozen --no-sync`.
- Сохранять минимальные зависимости и существующий стиль `scripts/`.
- Предпочитать небольшие предметные скрипты универсальным абстракциям.
- Не добавлять инфраструктуру и файлы без необходимости для текущей задачи.
- Численные выводы должны воспроизводиться из сохранённых данных кодом.
- Проверять предметные инварианты и сообщать о противоречиях.
- Утверждать, что проверка пройдена, только после её выполнения.

## Данные и происхождение
- `data/raw/` содержит только локальные исходники; не добавлять их в Git.
- Не исправлять исходные и обработанные данные без доказанного основания.
- Обоснованное исправление описывать вместе с исходным значением и причиной.
- Для каждого числа сохранять период, единицу и происхождение.
- Сохранять `source_id`, исходный CSV, строку и локатор публикации.
- Разделять наблюдения, расчёты, прогнозы, планы и предположения.
- Пропуск означает неизвестность; не заменять его нулём.
- Не складывать вложенные показатели, повторы и несопоставимые периоды.
- Расписание показывает план, а анонс не подтверждает эксплуатацию.
- Поток линии не считать конечным O&D или уникальными путешественниками.
- Не генерировать обратные направления без отдельного свидетельства.
- Отсутствие записи в выборке не доказывает отсутствие авиасообщения.

## Отчёты и результаты
- Markdown писать на русском, конкретно, простыми предложениями.
- Сначала давать вывод, затем числа, источники и ограничения.
- Субъективные веса и допущения обозначать явно.
- Строить графики из данных кодом; указывать единицы, период и источник.
- Проверять итоговое изображение визуально.
- Соблюдать границы задачи; не начинать следующий этап самостоятельно.
- Не трогать несвязанные изменения в Git; не создавать коммиты без запроса.
