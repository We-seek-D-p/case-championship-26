## Общая экономическая картина

Цифровые инициативы — продвижение пилота в существующих каналах и проверка предложений допуслуг и повторной покупки. Управление бронированием и допуслуги уже существуют. Ниже раздельные вклады за 2028 год; неизвестность не означает нулевой эффект.

| Составляющая | Базовый / осторожный сценарий |
|---|---|
| Новые перевозки: билетный результат после расходов программы | 877 /169 млн ₽ |
| Эффект канала и удержания | Не оценено |
| Дополнительная маржа допуслуг | Не оценено |
| Дополнительные затраты внедрения, вычитаются | Не оценено |
| Общий результат с учётом всех составляющих | Не оценено |

Общий результат — сумма трёх вкладов за вычетом дополнительных затрат внедрения.
Для измерения до пилота нужны продажи и расходы по всем затронутым рейсам, воронка
покупки и стоимость канала, история повторных поездок, продажи и себестоимость услуг,
а также смета IT, CRM и продвижения. На пилоте сравниваем тестовые и контрольные группы
за одинаковый период; финансы сверяют статьи затрат и пересечения с маршрутной моделью.
База, цели и денежные эффекты пока не определены.
[Формулы, план измерения и ответственные функции](../analysis/08-strategy-decision.md#план-измерения).

Смена канала не создаёт пассажира; в эффект канала входит экономия на сопоставимом билете,
а не его выручка заново. Для удержания учитывается только доказанный дополнительный
билетный результат вне уже учтённого маршрутного прироста. Для допуслуг считаем прирост
маржи после себестоимости, комиссий и возвратов. Расходы внедрения, канала и услуг
разносим без повторного вычета. До проверки этих условий суммарную оценку не публикуем.

## Пересборка и проверка

Python 3.14, uv; исходная модель и исследования не изменялись.

```sh
uv run --frozen --no-sync python scripts/check_strategy.py
uv run --frozen --no-sync python scripts/build_defense.py
```

Первый скрипт независимо сверяет арифметику, кресла и ротации, проверяет рейтинг и три предметных граничных случая. Второй собирает паспорт, презентацию и маршрутные таблицы из сохранённых CSV; `--passport-only` позволяет собрать только паспорт и таблицы. Нужен ReportLab: из окружения либо runtime Codex (`RUNTIME_PYTHON`). После пересборки нужно проверить страницы и визуально просмотреть PDF.

Сверка текущих PDF 10.11.2026: текст извлечён через `pdftotext`, число страниц проверено через `pdfinfo` — паспорт 3 страницы, презентация 8 слайдов. В паспорте есть цель №2, база сравнения, пилот, коммерческие предложения и прямое указание, что их отдельный эффект в модель не включён. Эта проверка содержания не заменяет визуальную проверку после следующей сборки. PDF и расчётные CSV при актуализации статуса не пересобирались.

Паспорт содержит поля [исходного шаблона](../case/templates/project-passport.docx), но текущие 3 страницы превышают лимит 1–2 страницы из задания. Сокращение и визуальная проверка остаются открытыми. Файлы `submission/templates/` — прежние образцы оформления, не финальные материалы. Содержимое текущих PDF и шаблоны `build_defense.py` проверяются отдельно: наличие формулировки в генераторе само по себе не подтверждает её наличие в PDF.
